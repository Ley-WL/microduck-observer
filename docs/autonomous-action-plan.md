# 自主行动功能规划

确认日期：2026-10-19。状态：**第一版已部署 runtime-20261019-autonomy-v1，默认关闭；实物验收待完成**。

本文作为自主行动功能的统一规划入口。先完成模式与控制交接，再逐步加入摄像头、ToF、喇叭和麦克风功能；不以规划代替实测结论。

## 第一版：先完成5件事

| 功能 | 已确认行为 |
|---|---|
| 开启与关闭 | 长按“自主行动”键1.5秒切换。每次按住只触发一次，松开后才能再次触发；按最新要求，开启与正常关闭都播放两声短叫。 |
| 开启条件 | 已经稳定站立，摇杆回中，没有其它动作正在执行。不满足时提示并拒绝开启，不自动从坐姿或倒地状态启动。 |
| 跌倒起身 | 自主模式下确认跌倒后，撤销自主移动目标并尝试起身。从确认跌倒开始总计最多6秒，包含等待、动作切换和起身，不因重试重置计时。确认稳定站立后恢复自主；超时失败则终止起身、卸力并退出。 |
| 手柄接管 | 有效手柄输入立即暂停自主输出，优先人工控制。摇杆回中持续1秒后，或人工动作结束且重新稳定站立后，恢复自主。 |
| 明确退出 | 再次长按自主键、停止、急停或卸力均退出自主模式，不在松键后自动恢复。正常关闭回到人工站立平衡；急停和起身失败则卸力。 |

**第一版开启后原地站立待命，不主动行走。** 先验收开关、声音、人工接管和跌倒恢复，再加入自主移动。

## 控制约定

- “模式是否开启”和“当前谁在控制”分开表达。人工接管是暂停自主输出，不是反复开关模式。
- 稳定站立须由现有平衡模型状态与有效反馈确认，不能只根据画面或机身直立判定。
- 起身期间普通行走输入不能把流程切成行走；停止和急停始终有效。已有故障、新鲜度及电压保护保持，不为自动起身绕过保护。
- 模型运行时保持原有舵机/IMU节拍，只有退出动作模型后才回到空闲15Hz。
- 叫声在实际状态切换后播放，播放不阻塞控制和6秒超时。开启、关闭的具体声音样式在实现时确定；拒绝开启和恢复失败需可区分的提示。
- 复用Rust后端的动作入口与唯一串口控制线程；未来感知模块只提交目标或检测结果，不直接写舵机。

主要状态为：关闭、自主待命/运行、人工接管、跌倒恢复。恢复成功回自主，明确停止或恢复失败回关闭。稳定站立阈值、摇杆死区等实现参数须结合现有控制逻辑确定并验证，不在本文中假设已验收。

## 第一版实现说明（2026-10-19）

Rust `autonomy.rs` 维护关闭、原地待命、人工接管、跌倒恢复四态；开机默认关闭，不持久恢复开启状态。实体十字键下和网页同位置均长按1.5秒切换，松开后才能再触发。网页显示模式、控制来源、起身剩余时间及退出原因。

开启要求当前原生50Hz平衡会话、连续500ms站稳（倾角<15°、角速度各轴<0.5rad/s、身体指令接近零）、新鲜反馈、摇杆/头部回中、其它技能及音频结束。手柄有效输入立即标记人工接管；明确回中1秒且动作结束、站稳后恢复待命。物理手柄接管网页会话时迁移自主会话归属，旧序号/外部会话无权续用。LB演示作为人工动作，结束后再恢复待命。

跌倒沿现有原生动作保护判据：平衡/金鸡的60°发令前保护，以及舞蹈45°保护，转入起身。坐下、拾取、翻滚等本身包含非直立姿态的人工技能保留其现有动作/故障保护，不能把有意姿态简单当作跌倒；不新增对它们所有姿态的通用跌倒识别。起身确认从getup模型中倾角<15°、各轴角速度<0.5rad/s、双腿相对HOME平均偏差<0.25rad连续500ms（且已执行至少0.5有效秒）判断；成功切回零速度平衡。判据是IMU/关节代理，不是足底接触测量。

总时限从跌倒确认的单调时钟起算6秒，覆盖技能切换、反馈暂停和推理；每轮读取前、有效观测后及发令前检查。到期返回原故障卸力路径，不重试或重置时钟。普通行走/技能不能中断起身；明确关闭起身中的自主模式也卸力，避免从倒地直接切行走。单元测试验证截止语义，真实停机延迟仍受50Hz调度/串口/操作系统影响，需实物测量。

声音复用设备现有音色：开启和关闭均为两声短叫、短叫拒绝、双长叫失败。模型运行时通过现有音频队列播放；停机通知由单独Rust音频工作线程回收aplay，不写舵机、不阻塞6秒计时。状态在后端先切换，音频故障不会阻止停止。物理手柄断连沿原停止控制路径退出；普通网页关闭后原地待命模式可继续，关闭自主或停止需显式操作。

软件与部署验证不等于动作验收。真实长按开关音色、人工接管/回归、正常起身、6秒失败卸力及急停仍须逐项现场测试；尚未启用摄像头追踪、ToF避障或麦克风指令。
