# MicroDuck 主板与 IMU 实测记录及注意事项

更新日期：2026-09-13。此文件可单独阅读，记录本次实物接线与调试结果。

## 1. 当前结论

Radxa ZERO 3W 已通过 I²C4 成功读取 GY-BNO085 的真实加速度、角速度和姿态四元数。连续采集 12.001 秒，I²C 读写错误为 0；角速度和姿态约 50Hz。

本次仅完成独立 IMU 验证。尚未把 BNO085 接入 MicroDuck 原控制程序，尚未验证真实舵机、行走模型推理、整机控制、安装坐标系和长期稳定性。

## 3. 最重要的纠错：编号方向

**之前助手将针脚编号起点认反，旧接线图作废。不要再从供电 USB-C 一端向下数。**

将主板正面（芯片面）朝上，摆成：排针在左、USB 接口在右、Wi-Fi 模块和天线在下。

- 针脚从下往上编号。
- 右侧内排（靠芯片）：从下往上 1、3、5……39。
- 左侧外排（靠板边）：从下往上 2、4、6……40。
- 1 号位于最下方、靠芯片的一孔，即 Wi-Fi／天线一端。

背面若摆成内存卡在上、两列焊点在右：最右侧靠板边的一列是偶数列，仍从下往上数。

纠错依据：官方位号图的 1 号标记，以及用户直接测实际 6、14 号焊点导通的结果。此前按反方向得到的“不响”和通信超时，不能用来证明主板或 IMU 损坏。

## 4. 已调通的六根接线

下表均为主板**物理针脚编号**，不是 GPIO 编号；孔位按上一节正面方向，全部从下往上数。

| 线色 | IMU 端 | 主板端 | 主板孔位 |
|---|---|---|---|
| 棕／灰 | VCC | 1 号，3.3V | 右侧内排，第 1 孔 |
| 红 | GND | 6 号，GND | 左侧外排，第 3 孔 |
| 橙 | SCL | 28 号，I2C4 SCL M0 | 左侧外排，第 14 孔 |
| 黄 | SDA | 27 号，I2C4 SDA M0 | 右侧内排，第 14 孔 |
| 绿 | PS1 | 9 号，GND | 右侧内排，第 5 孔 |
| 紫（替换原蓝线） | PS0 | 14 号，GND | 左侧外排，第 7 孔 |

注意本套线**红色是地，棕色才是电源**。换线后以两端引脚为准，不要用常见颜色习惯判断。

PS1、PS0 同时接地选择 I²C 模式；模式在上电／复位时采样。AD0、CS、INT、RST 本次没有另接线，保留模块默认状态。说明书给出的另一个地址是 AD0 拉低时的 0x4A，本次实际响应的是 0x4B。

## 5. 万用表实测

| 测试 | 用户反馈／结论 |
|---|---|
| 两支表笔尖相碰 | 会响，蜂鸣档可用 |
| 测试杜邦线各自两端 | 会响，所测线本身导通 |
| 按旧错误方向找“6、14” | 不响；测错位置，结果作废 |
| 按正确方向直接测 6、14 焊点 | 会响，实际两个 GND 导通 |

蜂鸣档操作：黑表笔插 COM，红表笔插 VΩmA；旋钮指向左下方声波符号。测通断时，主板必须拔电，IMU 连接线也应按测试要求断开。先碰两支表笔尖确认仪表正常。

若直接测背面 6、14 焊点：内存卡在上、焊点在右，测最右列从下往上第 3 和第 7 个。表笔不可同时跨到相邻焊点，不能强塞入排母插孔。

## 6. 真实 IMU 采集结果

日期：2026-09-13。三类报告均请求 20000 微秒间隔，即目标 50Hz。观察频率以收到的报告数除以测量时长计算，不等同于已验证每帧时延。

| 报告 | 12.001 秒内收到数量 | 观察频率 |
|---|---:|---:|
| 加速度 | 768 | 63.99Hz |
| 角速度 | 597 | 49.74Hz |
| 旋转向量四元数 | 596 | 49.66Hz |

- I²C 读写错误：0。
- 未解析报告：0。
- 产品 ID 响应原始十六进制：`f8010206dca49800c100000006000000`。

采集结束时的一帧：

| 数据 | 值 | 单位／顺序 |
|---|---|---|
| 加速度 | [-0.44922, -7.09375, 7.08594] | m/s²，x/y/z，含重力 |
| 角速度 | [-0.00391, 0, -0.00391] | rad/s，x/y/z |
| 四元数 | [-0.33398, 0.18835, -0.40179, 0.83154] | x/y/z/w |

加速度实际观察频率约 64Hz，不能写成所有传感器严格 50Hz；具体原因尚未单独验证。这一帧是测试当时姿态下的数据，不是以后必须匹配的标准值。尚未做运动响应、精度、安装方向和长期稳定性验证。

## 7. 当前系统配置与复测方式

`/boot/armbianEnv.txt` 中与本次测试有关的配置：

```ini
overlay_prefix=rk3568
overlays=i2c4-m0
user_overlays=microduck-i2c4-pullup-test
```

内部上拉测试 overlay 位于 `/boot/overlay-user/`，本次成功采集时仍然保留。尚未做移除它后的对照，不能宣称它是必须配置或已经撤销。修改前备份为 `/boot/armbianEnv.txt.before-pullup-test`，后续不要无条件覆盖已增加的其他启动配置。

登录后运行独立测试：

```bash
sudo python3 /home/radxa/microduck-debug/bno085_diagnostic.py
```

脚本使用 Linux i2c-dev 和 SHTP 协议，读取产品 ID，启用三类报告并采集约 12 秒，输出频率、计数和最后数据。正常结束时关闭本次启用的三类报告。它不控制舵机。不要与另一个正在读取同一 IMU 的程序同时运行。

脚本在电脑项目内的位置：`D:/Users/wl/Desktop/MicroDuck/scripts/bno085_diagnostic.py`。

持续实时查看（已部署到主板并短测通过，Ctrl+C 中断可正常退出）：

```bash
sudo python3 /home/radxa/microduck-debug/bno085_diagnostic.py --seconds 0 --refresh 0.2
```

`--seconds 0` 表示持续运行，`--refresh 0.2` 表示每 0.2 秒打印一次最新数据，不改变传感器报告间隔。输出中的 `age_ms` 是各类数据距最近一次接收的毫秒数，`io_errors` 为累计读写错误；旧数据不应被误认为新数据。按 Ctrl+C 停止后会关闭本次启用的报告。2026-09-13 约 5 秒实机试跑及 SIGINT 退出验证通过。

原简易探测脚本 `/home/radxa/microduck-debug/probe-imu.py` 只读取包头，可验证地址响应，不代表完整传感器测试。`Errno 6` 表示本次访问没有得到设备应答，`Errno 110` 表示超时；单凭这两种错误不能判定器件损坏。

本机 SSH 对 192.168.31.190 使用已核验的旧地址密钥别名：

```bash
ssh -o HostKeyAlias=192.168.31.191 -o StrictHostKeyChecking=yes radxa@192.168.31.190
```

此命令针对当前电脑已保存的主机密钥配置。换电脑或 IP 变化后需重新核实主机身份，不能直接关闭密钥检查。密码未复制到本文件，现有本地凭据文件在 `D:/Users/wl/Downloads/MicroDuck-Flash/board-login.txt`。

## 8. 操作注意事项与后续工作

实时脚本已增加 `euler_deg`：将归一化后的 xyzw 四元数按 ZYX 约定转换为 roll（绕 X）、pitch（绕 Y）、yaw（绕 Z），单位度。对应传感器坐标轴，尚未映射到机器人安装坐标系，yaw 不能直接当成已校准的罗盘航向。俯仰接近 ±90° 时欧拉角有奇异性，控制和姿态运算应保留四元数。转换通过单位姿态及三轴各 90° 的数值检查，并在板上运行 3 秒，读写错误为 0。

1. 改线前在主板执行 `sudo systemctl poweroff`，等待约 15 秒，再拔 Type-C 电源；不要带电改线。
2. IMU 只能按本模块要求接 3.3V，不能接物理 2、4 号的 5V。
3. 每次先确定实物方向和 1 号起点，再数孔；正面与背面左右相反。焊接看起来正常不能替代通断测量。
4. 测电压时需另切到直流电压档；不能在带电板上使用通断档。不要把红表笔插到 10A 孔测电源电压。
5. 本次错误接线后已经成功采集，但并未全面检查所有器件，不能保证不存在其他隐患，也没有证据表明 IMU 损坏。
6. 后续先做轻微转动／倾斜响应测试、较长时间采样，再确定 IMU 安装方向、坐标轴和控制程序的数据格式。
7. 接入 MicroDuck 时，需要另验证驱动兼容性、数据新鲜度、50Hz 控制周期和整机表现；本次独立测试不等于这些项目已完成。
