# 官方翻滚与落地恢复对照

2026-10-26，只读源码核查。官方pollen-robotics/microduck main commit 942e58e3aa6dbb28e7037203fff11866122c7567。源码副本见official/。

官方control.rs在动作窗口到期后才结束技能，翻滚默认窗口1秒（robotd.toml）；按住可以连续翻，松开也完成当前窗口。结束后按普通优先级选择站立/行走网络，未发现背朝下立即截断、额外伸腿0.5秒、强制接专用getup的同款流程。当前官方默认velstand同时负责零输入站立，不等于本机独立HD1910 getup权重。

官方另有limp_fall跌倒恢复：降低增益并跟随实时关节姿势让机体落地；新鲜gyro模<1rad/s连续200ms判静止，缺帧重计；最长1500ms也可转入整理姿势（这是超时出口，不是确认静止）。从当时实测关节角线性600ms整理到默认姿势，重置控制器，零输入交回普通策略。它明确在controller.busy或坐姿时不启动，因此不直接插进主动翻滚，也不是每次翻滚结束必经步骤。官方gain_limp=50/pose_gain=160属于其硬件，不能按数值移植本机P5D0。

本机此次roll0.8秒背朝下截断时gyro模7.372rad/s，伸腿0.5秒后在1.3秒交getup仍2.311rad/s；随后起身0.5秒为1.903、1秒1.556、1.5秒0.567、2秒0.230。交接未确认落地静止，半秒计时不等于稳定证据。后续颈部卡在约44°并报fault8为已证现象，但不能证明提前交接为唯一根因。

建议先以完整动作窗口交回零输入平衡作为官方基线做配对仿真；若仍维持用户此前背朝下停止的自定义目标，则借鉴其静止检测、从实测姿态整理、重置控制器的恢复顺序，并明确标记为HD1910适配方案，不冒称原封不动官方翻滚。必须验证颈部接触/跟随，不能仅延长计时或取消故障保护。此次没有修改运行代码、模型、参数或部署，没有发送动作。
