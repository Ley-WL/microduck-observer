## 2026-09-21 Web 观测服务接入

- 按用户要求在主控部署独立观测后端和构建后的前端，访问地址 `http://192.168.31.193:8877/`，代码在本仓库 `web-debug/`。
- systemd 服务 `microduck-observer` 已启用开机启动，使用 `/home/radxa/microduck-observer/current` 和独立 Python venv。服务用户 radxa，通过 i2c 补充组访问 `/dev/i2c-4`；udev 规则只针对该设备设置 root:i2c、0660。
- 部署前确认 robotd 未运行、未发现其他 IMU 采集进程；服务不打开舵机设备。以后运行独立诊断或接入原运行时前，必须先停止 `microduck-observer`，避免争用 IMU。
- 实机流发布加速度、角速度和 `imu.orientation` 传感器四元数；安装方向未校准，不发布机器人 `pose`。这次完成的是 Web 实时观测接入，仍未接入 MicroDuck 原运动程序。
- I2C 先读取 4 字节头再完整读取时，第二次读出的 SHTP 头可能带 continuation 标记，这是该传输方式的正常行为，不能直接当作坏包拒绝；已按原成功诊断逻辑处理，并添加回归测试。
- 主控采集端实测角速度/四元数约 49.75 Hz、加速度约 63.81 Hz；12.010 秒 LAN WebSocket 测试接收朝向 450 帧、IMU 449 帧，约 37.5 Hz。采集和网络推送频率分别报告，I/O 错误、未解析报告和采集队列丢弃均为 0。
- 未进行整机重启、运动响应、安装方向校准或长期稳定性验证。部署维护细节见 `web-debug/deploy/README.md`。
