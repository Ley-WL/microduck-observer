# Web 模型控制接入计划

日期：2026-10-01。状态：前端操作面板已实现并部署；模型推理和实机输出未接入。姿态数值、四元数和标定说明已移入左侧 IMU 区。

## 已核对的来源和模型

官方源码：平级 microduck-upstream，pollen-robotics/microduck，提交46a380b。控制编排见robotd/src/control.rs，观测协议见duck-control/src/obs.rs，关节表见duck-control/src/model.rs。主控实存/home/radxa/microduck-policies-v5/manifest.json及下列十个模型；manifest声明XL330、50Hz、61维输入/14维输出。文件存在不等于已完成HD1910迁移验证。

| 模型 | 作用 | 接入顺序 |
|---|---|---|
| alpha_stand | 连续站立策略 | 第一阶段闭环站立 |
| velstand | 行走且零移动命令时站立，v5默认walk槽 | 第二阶段方向控制；确认静止行为后用于日常站走切换 |
| alpha_walking | 另一套持续步行策略 | 对照/可选，不和velstand同时执行 |
| alpha_sitstand | 姿态标志1坐下、0起立 | 站立之后接入坐起转换；不是任意仰卧起身模型 |
| alpha_ground_pick | 周期相位驱动低头拾取 | 第三阶段技能 |
| ball_kick_left / ball_kick_right | 左右踢球 | 第三阶段技能 |
| roulade | 翻滚 | 第三阶段，核对入口姿势及结束交接 |
| roller / roller_crouch | 轮式行驶/下蹲 | 与步行机械配置分开；当前双足配置不开放执行 |

主控另有/home/radxa/microduck-shadow/models的7个旧模型，不能仅凭seat/rise/recovery文件名当成当前官方v5能力；界面默认显示v5来源、模型名、版本和可用槽。

## 界面与功能键

继续3:4:3单屏布局：左侧IMU姿态/四元数/角速度/加速度，中央3D实测模型与控制面板，右侧15舵机反馈/手动角度。截图中的数值和说明已移左侧；中央控制面板后续按本方案实现。

中央下方用固定高度区域，三行：

1. 模式与运行：手动 / 模型预览 / 实机控制；模型选择；开始模型、停止模型、全部失能。
2. 日常控制：模型站立、坐下、起立；方向摇杆/前后左右/转向；归零移动命令；头部回正、身体回正；嘴部开合0–30°独立控制。
3. 可折叠技能：低头拾取、左踢、右踢、翻滚；未接入或机械模式不适用时明确显示状态，不提供假可用按钮。

状态只显示当前模型、模式、实际控制Hz/最大间隔、推理耗时、最后错误；固定高度避免撑高页面。预览叠加模型预测目标（淡色）与真实机器人（实色），可显示各关节预测/实测误差，避免把预测动画当作实际运动。

键盘建议：W/S前后、A/D横移、Q/E转向；松键和窗口失焦将移动命令归零；Esc归零并回到模型站立（仅运行模型且支持时）；独立“全部失能”按钮始终可用，可加Shift+Esc。输入框、标定对话框和未选中控制区时不接管键盘。速度方向命令是用户意图参数，并非额外加入舵机限速/限加速度门槛；按模型训练接口定义物理量。

语义明确：
- 现有“站姿保持”是固定角度目标，另名“静态站姿”；新“模型站立”是持续读取IMU/关节并推理的闭环。
- “停止模型”：停止策略输出，接管为保持停止时实测角度，不追赶最后一个策略目标；这是舵机位置保持，不保证自主平衡。
- “全部失能”：停止策略并取消排队指令、所有15颗卸力，不再由下一帧重新使能。
- 坐下/起立属于持续策略状态转换，不能用一次ONNX推理充当完整动作。
- 预览启动不发舵机指令；实机执行要明确切换运行模式，按钮不混用。

## 主控执行架构

浏览器仅发送模式、方向/头身命令及技能选择，通过WebSocket回传状态；不从浏览器每20ms请求ONNX或逐关节POST维持闭环。策略循环在Radxa本地运行，目标50Hz，独立记录真实发令统计与推理耗时。

数据链：IMU原始角速度/安装换算后的重力方向 + 14关节位置/速度 + 上一策略动作 + 13维命令 → ONNX → 默认关节姿态+action_scale×输出 → 关节名/ID/标定方向换算 → 现有HD1910串口所有者同步写目标。

须按每个文件实际metadata/manifest核对关节顺序、home pose、action_scale、归一化、隐藏状态/重置规则。官方数组顺序是左腿、头颈（跳过嘴）、右腿；观测台采集ALL_IDS顺序不同，必须按名称或ID映射，不能直接zip。官方alpha策略不控制第15颗嘴舵机；嘴部独立用户命令。官方model.rs已明确嘴部打开30°，与用户指定0–30°一致。

执行策略与手动滑块/站姿/标定共用一个串口所有者和一个控制权。模型运行时手动接管须停止策略后再下发，避免两路争写；全部失能走最高优先级取消。官方Dynamixel总线、增益单位、IMU总线地址不能直接用于飞特HD1910和MS901M。

IMU需要使用真实安装矩阵对角速度与重力同时换算。显示参考姿态不等于世界重力归零，仰卧标定后重力方向仍须物理正确；验证站/仰卧/前倾/侧倾的重力轴与角速度方向。现有仰卧零点必须转换成模型训练的关节角，而非强行拿仰卧当模型home pose。

关节速度优先核对HD1910实际速度反馈及单位，或经采样时间核验后的差分估算；不以网页平滑动画或异步HTTP时刻充当机器人速度。推理在本地共享快照读取，复用现有实时采集，不新增逐帧HTTP采样。

保留用户既定规则：官方关节范围、嘴部0–30°、工作电压4–8.4V、真实硬件fault、全部失能。不得恢复55步跟随、负载300、8步漂移、1024步距离或推算速度门槛，也不盲目照搬官方XL330 gain=200/160。模型训练的滤波/动作缩放与舵机速度限值是不同机制，需要按模型协议实现并展示依据。

连接丢失需撤销移动指令；主控控制状态决定保持模型站立或停止策略，不依赖浏览器定时器。端到端处理必须含明确的命令会话/序号与取消机制，防止旧客户端恢复后重放动作。

## 落地顺序与验收

1. 模型列表和预览：读取v5清单、装载/校验模型，显示预测叠加、输入有效性、推理与实际循环统计；不写电机。现有shadow脚本可复用输入换算和诊断部分，但HTTP轮询不能直接充当控制循环。
2. HD1910接管适配：复用唯一串口，确认关节/home/IMU映射和目标同步写；接入单一alpha_stand，现场验证从已摆站姿持续运行/停止/失能。官方仿真或只读推理通过不是实机平衡结论。
3. 坐起与方向控制：接alpha_sitstand及velstand，核对坐起状态转换/默认命令；验证坐下起立、零命令站立、前后/横移/转向。不要把坐姿起立宣称仰卧自主起身。
4. 技能：按manifest实现相位/时长/交接，再逐个接拾取/踢球/翻滚。轮式模式按硬件另行适配。

每阶段记录日期、模型hash/manifest版本、标定revision、实际Hz/时延、动作结果及取消/失能结果。实机动态匹配（HD1910扭矩速度响应、关节方向、IMU轴）仍须验证，当前计划不宣称已有自主站稳或行走成功。
