# Observer 更新与多设备连接

App 0.9.53（72）支持查看所选设备的 Observer 版本、发起主板服务更新、保持多台 BLE 连接并切换控制。Observer 0.9.1 开始提供配套协议。手机 App 更新与主板 Observer 更新是两个独立入口。

## 用户入口

- `设备 → 主板`：查看 Observer 版本及部署标识，点击“检查 Observer 更新”。更新针对当前选中的设备；切换设备后旧更新对话框不能更新新设备。
- 更新前托稳、急停卸力；15 个舵机必须在线、全部失能且反馈新鲜。主板需要能联网下载更新。更新中不启动动作、不断电，服务重启会短暂断连。
- `设备 → 连接`：搜索并选择另一台鸭子。已连接设备列表提供“切换控制”。先确认原设备控制线程停止，再切换；原设备停止未确认时保留原控制对象。
- 非选中设备只接收零意图心跳；不复制动作或摇杆状态。每台设备的加密会话、序号、反馈缓存和绑定密钥分开。后台长连保留，失联清该设备状态；非选中设备失联后可重新搜索连接。

## 新设备

首次部署 Observer 0.9.1 或更新版本后，未绑定设备使用 App/服务共同的固定初始化码，不需要人工输入。此码用于应用协议首次建立所有者密钥，不是 Android 系统配对 PIN。

已有绑定继续使用原所有者密钥，不旋转 BLE 身份、不清除绑定，也不允许其它手机用固定码覆盖既有所有者。手机旧版单设备绑定自动迁移，设备密钥按 robotId 分别加密保存。

新设备要具备 OTA，除 Observer 主服务外需安装 Rust 更新助手、公钥和 socket 单元。完成 ARM `--bins` 构建后，离板执行：

```powershell
python tools/provision-observer-ota.py --host radxa@设备地址 --port 22 --password-file 本机登录记录.txt
```

登录记录沿用本机 `Password: ` 格式；不要将密码记录或签名私钥放入项目、镜像或公共下载目录。公钥 `deploy/ota-public.pem` 可分发。初始化安装同样要求先卸力，只启用 socket，不运行实机动作。

## 架构与发布

App 通过已认证 BLE 发送 `observer-ota` 的 `check/apply`。主服务验证当前启动标识、确认标志、任务互斥和新鲜失能反馈；通过受限 Unix socket 请求 root Rust 助手。助手仅接受固定的检查/安装操作，不能接受 App 指定的 URL、路径或 shell 命令。

助手从固定下载源读取 RSA/SHA256 签名清单，每次验证使用独立临时目录。它检查版本序号、签名、文件长度/SHA256 和 ARM64 ELF；复制当前 release，只替换服务二进制，保留其它模型、网页和运行库。安装前再次检查失能状态，正常安装失败恢复原 release。标定、增益和 BLE 身份文件在外部保留并校验；历史 release 作为回滚来源保留。

主服务重启后，在安装验收结束前重新占用动作门，避免重连后的新动作打断只读验收。急停卸力入口仍可用。超过助手运行预算的状态会显示更新超时，可重新检查；不将断电/强杀恢复声称为已验证的自动回滚。

发布工具只在开发电脑运行：

```powershell
python tools/publish-observer-ota.py --binary backend-rust/target/aarch64-unknown-linux-gnu/release/microduck-observer --version 0.9.1 --code 新的递增序号 --output deploy/staging/observer-ota-public
```

`--deploy` 从标准输入读取云服务器密码，使用已记录的 SSH 主机密钥上传二进制后原子替换清单。签名私钥默认从开发电脑用户目录读取，不上传；已发布序号不能改成不同二进制。主板长期运行的主服务和更新助手均为 Rust，Python 仅用于离板发布、初始化安装和验收脚本。
