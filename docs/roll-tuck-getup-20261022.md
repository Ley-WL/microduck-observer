# 翻滚后快速躺倒并起身（2026-10-22）

用户要求：翻滚2秒后快速躺倒，确认IMU姿态后直接交给倒地起身，再回行走。

## 实现

- 前2秒运行当前HD1910翻滚actor，记录其0.10秒输出的收腿目标。
- 2秒后主动发送该收腿目标，仍经过现有机械/编码限位。不是锁定落地时的关节位置，也不增大P/D。
- 当前有效IMU倾角60～120°、角速度模<4rad/s即交给 `xgoduck_getup`，无额外稳定等待。这里只是躺倒姿态代理，IMU无法证明地面接触。
- 切入起身清空raw action和EMA历史，采用起身原有0.45旧/0.55新滤波；不切坐站模型。
- 起身原有完成条件：至少3秒，倾角<15°、角速度模<2rad/s、10腿关节平均HOME偏差<0.25rad连续1秒，然后零速度行走。
- 收腿至总4秒仍不满足交接条件，或起身10秒未完成，则报错并卸力。急停、反馈失效保护保持。
- 手动待执行动作保留原优先级；模型权重、增益、标定、遥控映射未修改。
- 模型包内原 `durationSeconds=1.5` 是已有artifact验证字段，本版运行状态机明确覆盖旧定时切行走行为；遥测 `rollExitRevision=roll2s-tuck-getup-v1`、`rollPhase` 可识别。

## 验证

纯等待躺倒的方案32例均未进入起身；主动收腿采用0.10秒目标，筛选32/32通过，0.20/0.30秒目标分别24/32、14/32，不采用。

锁定0.10秒后，两个新seed 221227/221231、各32环境，加入原生50Hz起身角速度/关节速度滤波及raw历史/动作EMA，64/64完成翻滚、起身、交回行走，并满足末1秒低运动标准。起身接管2.24～2.82秒，回行走5.24～6.46秒，零环境重置。

环境为7.4V HD1910 BAM/Observer限位、roll接触模型、无扰动无物理随机化；不能视作实机成功率或精确执行器复现。原2秒切行走也曾名义32/32而实机失败，因此本轮实机仍需用户验证。

285 Rust测试通过、1忽略，ARM release构建通过。旧锁姿草案已撤除。
