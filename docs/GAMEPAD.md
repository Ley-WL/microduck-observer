# 主板直连手柄（开发版）

2026-10-14：面向用户提供的盖世小鸡 GameSir T4 Nova Lite（Xbox 按键布局），直接连接 Radxa Linux 主板，无需电脑网页或手机转发。当前为本地实现，**尚未取得此手柄的实际设备名称、VID/PID、轴映射和断连行为；未部署、未通过实物验收**。图片列出蓝牙/有线/2.4G，不足以证明三种模式在当前 Armbian 内核均受支持。

蓝牙手柄由主板 BlueZ/HID 驱动提供 evdev，App 继续使用 Observer BLE GATT；本次仅移除软件连接排斥，不代表主板蓝牙双连接射频稳定性已通过实测。

## 输入与控制

- Linux evdev 当前状态每 40ms 读取一次，实际执行沿用 Rust Motion、模型会话、递增序号、共享标定和唯一 UART owner；不改变模型、增益、机械限位或既有故障保护。原始按键与摇杆状态另以 25Hz 发布到 gamepad 遥测，网页橙色高亮仅表示主板收到了该物理输入。输入超过 500ms、连接断开或遥测失联时清空高亮。
- 默认关闭。必须配置具体 `/dev/input/` 设备路径和内核返回的精确名称；不自动挑选第一只手柄，不自动配对或信任附近蓝牙设备。
- 接入/重新连接时必须全部松开且双摇杆回中。LB+A 明确取得控制权并站起（倒地时可用 LB+Y 直接取得控制并起身）；初始连接不会运动。App 与手柄可同时保持连接，连接/认证/空闲心跳不占运动控制权。另一端正在控制时仅拒绝运动请求，保留连接和状态读取；当前端停止保持（App 的 idle、手柄 B）、超时或断连后释放控制，另一端无需重连，显式发起动作即可取得控制。网页仍沿用原模型会话/任务互斥。
- 行走模型就绪后，须再次全部松开并回中，然后按住 LB 才接受摇杆。模型切换、反馈暂停或动作按钮会撤销摇杆使能，需重新松开回中。每个动作只处理按下边沿，长按不会重复触发。
- 左摇杆上/下前后行走、左/右转向；右摇杆上/下抬低头、左/右转头。15% 中心死区（内核更大的 flat 优先），连续比例输出；首版速度系数固定 0.5，对应现有接口前进最大 0.2m/s、转向最大 0.5rad/s。此为指令上限，不是实测速度。

| 按键 | 功能 |
|---|---|
| LB+A，双摇杆回中 | 取得控制并站起；启动失败显示日志，不自动重试 |
| LB+左摇杆 / 右摇杆 | 身体 / 头部控制；松 LB 方向归零，继续模型平衡 |
| LB+X | 坐下，需已取得手柄控制 |
| Start | 预留按键，当前不执行动作 |
| LB+Y，双摇杆回中 | 倒地起身，可直接取得控制；不会先执行站起 |
| LB+RB | 嘎一下，需已取得手柄控制 |
| B | 停止自己的模型、保持并释放控制权 |
| Back / Select | 全局急停卸力，手机控制期间也有效；再次启动必须回中后明确 LB+A |

evdev 读取失败/设备移除时停止自己的模型并保持、释放控制权；任务采样间隔超过 250ms 同样撤销使能。已有模型指令 250ms 失联归零与头部超时保留。**查询内核状态不是无线数据包心跳**：某些 2.4G 接收器掉线仍保留 evdev 节点；若其驱动保留旧按键/轴值，本机无法仅凭 evdev 判断无线掉线。实测断连必须覆盖所用连接模式，未核验前不得把它当已验证失联保护。

## 连接测试需要的主板配置

蓝牙配对由 Linux BlueZ/桌面配对工具完成；程序不主动扫描、配对或建立蓝牙连接。配对与 HID 连接成功后，需配置 systemd drop-in 中的三个设备变量，再更新并重启 Observer 服务，evdev 运行器才会打开手柄。变量默认未设置，因此只配对手柄或仅更新网页不会启用主板手柄控制。

部署前建议先只读识别设备、确认模式下按键轴编号，再启用运行器。启动后应能从日志和网页遥测看到连接状态；按键输入会在网页同步高亮。控制动作尚需逐项实机验证。

## 先只读识别

在主板上接入 USB 数据线或接收器；蓝牙先使用主板原有蓝牙管理工具配对明确的目标手柄，具体组合键以该手柄说明书为准。推荐先核验 Xbox/XInput 输出模式；Switch/Android 模式不能仅凭相似设备名复用配置。

```sh
python3 tools/inspect-gamepad.py
python3 tools/inspect-gamepad.py /dev/input/eventN --watch
ls -l /dev/input/by-id/ /dev/input/by-path/
```

该工具仅输出设备名称、bus/VID/PID、轴范围和当前按键，不调用运动接口。逐一确认：左摇杆 ABS_X=0/ABS_Y=1；右摇杆 ABS_RX=3/ABS_RY=4（或经确认 ABS_Z=2/ABS_RZ=5）；水平左负右正、垂直上负下正。按键必须是 A304/B305/X307/Y308/LB310/RB311/Back314/Start315。设备必须提供全部这些按键与四个有效轴，否则运行器拒绝打开。布局不同暂不启用，保存识别结果后再补对应配置；不凭产品宣传图猜 VID/PID。

## 配置示例（不自动安装）

新二进制部署后，使用 systemd drop-in。将两处占位符换成只读识别得到的稳定路径和完整名称，避免 eventN 在重启后变化：

```ini
[Service]
SupplementaryGroups=input
DeviceAllow=char-input r
Environment="MICRODUCK_GAMEPAD_DEVICE=/dev/input/by-id/实际设备-event-joystick"
Environment="MICRODUCK_GAMEPAD_NAME=实际完整设备名称"
Environment="MICRODUCK_GAMEPAD_RIGHT_AXES=3,4"
```

现服务 `DevicePolicy=closed`，需要 input 组和设备读取许可；不得删除原 i2c/dialout/robot/audio 等已有组或设备许可。`char-input` 支持设备重连后 minor 变化，只授予读取；部署时确认内核 input 字符设备组存在。蓝牙没有稳定 by-id 时按实际 VID/PID/蓝牙身份设置 udev 稳定链接，不能把示例名称直接当有效配置。移除三个环境变量并在卸力状态重启服务可关闭手柄入口。

## 网页虚拟手柄

“姿态与 IMU”中的模型控制改为可直接操作的手柄外观。鼠标或触屏按住左摇杆行走/转向、右摇杆转头，支持两根摇杆分别按住和释放；网页不要求同时按 LB。按钮标注其动作，A 站立、Start 预留、X 坐下、Y 倒地起身、B 停止保持、Back 急停卸力、LB 拾取、RB 嘎一下，十字键上方舞蹈、左侧左脚踢球、右侧右脚踢球、下方自主行动；舞蹈、左右踢球和自主行动显示为待接入的禁用入口，不发送动作请求。原翻滚入口移至“按键说明与诊断”；红色按钮急停卸力。原指令速度、模型状态与诊断保留。

网页继续使用本页的模型会话与递增序号，不接管 App/物理手柄启动的模型；需先停止后在网页明确启动。指针取消、页面失焦/隐藏、反馈未就绪、动作切换和请求失败清空双摇杆。右摇杆需 `/api/v1/policy` 声明 `webHeadControl:true`，并使用支持头部偏转的原生行走模型；旧后端不显示为可用。后端 `/policy/command` 对可选 `headPitch/headYaw` 校验有限值/±1范围、模型就绪、会话及递增序号；不含头部字段的旧BLE续约不会覆盖其头部输入。
