| LB | 演示 / 取消：站稳后独立按下，约28～35秒 |
| RB | 拾取：模型就绪、摇杆回中、独立按下 |
| RT | 嘎一下：单按短叫、双击两声、长按长叫 |
| LT（按住） | 行走速度翻倍：默认 0.2 m/s，按住为 0.4 m/s；松开恢复默认 |
| B | 停止自己的模型、保持并释放控制权 |
| Back / Select | 全局急停卸力，手机控制期间也有效；再次启动需回中后长按 Y |

evdev 读取失败/设备移除时停止自己的模型并保持、释放控制权；任务采样间隔超过 250ms 同样撤销使能。已有模型指令 250ms 失联归零与头部超时保留。**查询内核状态不是无线数据包心跳**：某些 2.4G 接收器掉线仍保留 evdev 节点；若其驱动保留旧按键/轴值，本机无法仅凭 evdev 判断无线掉线。实测断连必须覆盖所用连接模式，未核验前不得把它当已验证失联保护。

## 连接测试需要的主板配置

网页“连接实物蓝牙手柄”入口由主板调用 `bluetoothctl`/BlueZ 扫描，用户选定地址后依次配对（已有配对则跳过）、信任并连接；不会自动连接或信任扫描到的设备。配对前手柄关机，同时短按 B + Home 进入配对状态（按键步骤以厂商手册为准）。服务账户必须能访问 BlueZ D-Bus，服务 unit 需允许读取 Linux input 字符设备；更新 unit 后需重启 Observer 服务。2026-10-17 起，新程序在蓝牙连接产生兼容 evdev 节点后自动识别并发布输入；新板安装器自动配置 input 组与字符设备读取权限。仅蓝牙连接但驱动未提供兼容节点时仍不能采集输入。BlueZ/Polkit 权限不足、没有 `bluetoothctl` 或无默认适配器时，网页显示具体失败信息。

扫描/连接接口：`POST /api/v1/gamepad/bluetooth/scan` 请求 `{}`；`POST /api/v1/gamepad/bluetooth/connect` 请求 `{"address":"AA:BB:CC:DD:EE:FF"}`。连接接口严格校验 MAC 字符串并只操作该地址。设备发现时网页会提示可能的手柄名称，但最终由用户核对后选择。

部署前建议先只读识别设备、确认模式下按键轴编号，再启用运行器。启动后应能从日志和网页遥测看到连接状态；按键输入会在网页同步高亮。控制动作尚需逐项实机验证。

## 先只读识别

在主板上接入 USB 数据线或接收器；蓝牙先使用主板原有蓝牙管理工具配对明确的目标手柄，具体组合键以该手柄说明书为准。推荐先核验 Xbox/XInput 输出模式；Switch/Android 模式不能仅凭相似设备名复用配置。

```sh
python3 tools/inspect-gamepad.py
python3 tools/inspect-gamepad.py /dev/input/eventN --watch
ls -l /dev/input/by-id/ /dev/input/by-path/
```

该工具仅输出设备名称、bus/VID/PID、轴范围和当前按键，不调用运动接口。逐一确认：左摇杆 ABS_X=0/ABS_Y=1；右摇杆 ABS_RX=3/ABS_RY=4（或经确认 ABS_Z=2/ABS_RZ=5）；水平左负右正、垂直上负下正。按键必须是 A304/B305/X307/Y308/LB310/RB311/Back314/Start315。设备必须提供全部这些按键与四个有效轴，否则运行器拒绝打开。布局不同暂不启用，保存识别结果后再补对应配置；不凭产品宣传图猜 VID/PID。

## 可选手工指定（多手柄或特殊部署）

新板默认无需设置以下三个环境变量；已有明确配置优先。需要固定特定手柄时使用 systemd drop-in，将占位符换成实际稳定路径和完整名称，避免 eventN 在重启后变化：

```ini
[Service]
SupplementaryGroups=input
DeviceAllow=char-input r
Environment="MICRODUCK_GAMEPAD_DEVICE=/dev/input/by-id/实际设备-event-joystick"
Environment="MICRODUCK_GAMEPAD_NAME=实际完整设备名称"
Environment="MICRODUCK_GAMEPAD_RIGHT_AXES=3,4"
```

现服务 `DevicePolicy=closed`，需要 input 组和设备读取许可；不得删除原 i2c/dialout/robot/audio 等已有组或设备许可。`char-input` 支持设备重连后 minor 变化，只授予读取；部署时确认内核 input 字符设备组存在。蓝牙没有稳定 by-id 时按实际 VID/PID/蓝牙身份设置 udev 稳定链接，不能把示例名称直接当有效配置。移除三个环境变量并在卸力状态重启服务会恢复自动发现；要禁止实体动作请开启并保存网页只读调试模式。可运行 `microduck-observer --verify-gamepad` 只读验证自动识别，执行账户须有 input 组权限；该命令不启动运动服务。

## 网页虚拟手柄

“姿态与 IMU”中的模型控制改为可直接操作的手柄外观。鼠标或触屏按住左摇杆行走/转向、右摇杆转头，支持两根摇杆分别按住和释放；网页不要求同时按 LB。按钮标注其动作，A 站立、Start 预留、X 坐下、Y 倒地起身、B 停止保持、Back 急停卸力、LB 拾取、RB 嘎一下，十字键上方舞蹈、左侧左脚踢球、右侧右脚踢球、下方自主行动；舞蹈、左右踢球和自主行动显示为待接入的禁用入口，不发送动作请求。原翻滚入口移至“按键说明与诊断”；红色按钮急停卸力。原指令速度、模型状态与诊断保留。

网页继续使用本页的模型会话与递增序号，不接管 App/物理手柄启动的模型；需先停止后在网页明确启动。指针取消、页面失焦/隐藏、反馈未就绪、动作切换和请求失败清空双摇杆。右摇杆需 `/api/v1/policy` 声明 `webHeadControl:true`，并使用支持头部偏转的原生行走模型；旧后端不显示为可用。后端 `/policy/command` 对可选 `headPitch/headYaw` 校验有限值/±1范围、模型就绪、会话及递增序号；不含头部字段的旧BLE续约不会覆盖其头部输入。

2026-10-14 网页蓝牙扫描与配对入口、Rust接口已部署到 230；主服务 161 项通过/1 项忽略，ARM64 release、网页构建与72项前端测试通过。230扫描接口返回了 `Xbox Wireless Controller` 疑似设备；未执行配对、trust/connect 或舵机动作。配对入口不代表 evdev 路径/按键轴已识别，当前实体输入控制仍待单独启用和实测。模型手柄其他交互保持原有行为。

## 左右脚踢球（本地集成，主板暂未更新）

网页十字键左/右分别踢球；实体手柄双摇杆回中后十字左/右直接触发一次，不按住重复。须先进入站立行走平衡，执行0.5秒后回行走；App旧服务无对应模型时按钮禁用。舞蹈/自主行动仍预留。

## LB演示

演示由Rust原生模型循环执行，复用现有模型与音频；不新增Python运行服务，不改变模型、增益或标定。请求需当前控制会话及递增序号；网页每120ms续期、实体输入每40ms续期，500ms无有效续期退出。只支持原生50Hz模型运行器，稳定站立至少500ms且摇杆回中才接受。

| 阶段 | 内容 | 预计时间 |
|---|---|---|
| 开场 | 短叫，头左右转再回正 | 2.8秒 |
| 坐站 | 坐下、短叫、站起并等稳定 | 约4～7秒，按模型完成及站稳推进 |
| 前后移动 | 前进1.5秒、停稳；后退1.5秒、停稳，穿插短叫 | 约4～5秒 |
| 拾取 | 等动作完成回到平衡，再双叫 | 约4～6秒 |
| 舞蹈 | 执行现有舞蹈，中途短叫及双叫，回到平衡 | 约8.5秒 |
| 收尾 | 左右上下转头、长叫，回正 | 4.8秒 |

前后指令速度0.15m/s；距离依实际步态与地面变化，不保证回到原点。每阶段既检查时间又检查实际技能切换/站稳，不以固定延时假装动作成功；全程55秒、单阶段9～12秒上限。

再次LB或有效人工输入取消剩余序列并清音频队列；坐姿请求原站起动作，其他阶段请求回平衡。实际技能切换期间原有手动准入门继续生效，可能需要回平衡后再次输入。B停止保持、Back卸力沿原逻辑。掉线、反馈中断、模型故障不会续跑演示；跌倒沿各现有技能保护，退出后不自动爬起。本功能不包含未来自主行动恢复流程，也没有加入火烈鸟、翻滚或踢球。

验证边界：状态机模拟全流程28～35秒、控制手势/超时/会话隔离及编译验证不代表实物动作成功；实物整段演示及中断仍需现场验收。
