## 重构重点

| 重点 | 当前实现 |
| --- | --- |
| 统一控制后端 | HTTP、WebSocket 与 BLE 在同一 Rust 主服务内接入，共用动作状态、控制会话和硬件反馈，移除旧 Python 服务与蓝牙转发控制链路。 |
| 串口唯一拥有者 | 舵机采集、目标写入、使能、卸力和校准由同一个总线拥有者串行处理，网页、App 和推理任务不另开舵机串口。 |
| 模型合同显式化 | ONNX 权重与 metadata 配套，核对哈希、观测维度、关节顺序、归一化和执行配置；动作历史、滤波、增益与切换按具体模型合同处理。 |
| 真实反馈驱动显示 | 3D 关节使用实际编码器反馈；IMU、关节、系统与日志独立维护时间戳、序号、有效性及过期状态。页面接收心跳不会把旧传感器数据刷新为实时。 |
| 标定与设置统一持久化 | Web 和 App 共用主板保存的关节零位、方向、IMU 参考、安装轴向及独立模型增益；共享标定使用 revision 防止并发覆盖。 |
| 系统权限隔离 | Wi-Fi 与关机/重启由受限 Rust 辅助服务通过 Unix socket 提供，主控制服务无需 root 权限。 |
| 可验证发布 | 独立 release、候选只读核查、文件哈希验证、原子切换与回滚；升级保留现有模型、标定、增益和 BLE 身份。网页资源可单独更新，不重启控制服务。 |

## 系统架构

```mermaid
flowchart TB
    Web["Web 工作台<br/>Vue 3 · TypeScript · Three.js · ECharts"]
    App[DuckLink Android App]
    Gamepad["T4 Nova Lite 手柄<br/>本地开发 · 待实测"]
    Gamepad -->|BlueZ HID / Linux evdev| API
    Web <-->|HTTP / WebSocket| API
    App <-->|认证加密 BLE · BlueZ| API

    subgraph Board[机器人主板 · Linux ARM64]
        API["Rust 主服务<br/>Axum / Tokio · 控制会话与动作入口"]
        Telemetry["遥测缓存<br/>最新样本 · 时间戳 · 有效性 · 日志"]
        Bus["舵机总线唯一拥有者<br/>反馈读取 · 目标写入 · 校准 · 卸力"]
        Policy["模型运行器<br/>ONNX Runtime CPU · 模型合同 · 技能切换"]
        IMU[IMU 独立采集线程]
        State["持久状态<br/>共享标定 · 模型增益 · BLE 身份"]
        Helpers["受限 Rust 辅助服务<br/>Wi-Fi 管理 · 系统电源"]
        API <-->|状态订阅| Telemetry
        API -->|显式控制命令| Bus
        Bus <-->|观测与目标| Policy
        Bus -->|关节反馈| Telemetry

        IMU -->|姿态与角速度| Policy

        Policy -->|读取执行配置| State
        API <-->|Unix socket| Helpers
    end

    Bus <-->|TTL UART · 1 Mbps| Servos[15 个 HD1910 舵机]
    Sensor[MS901M UART IMU] --> IMU
    Files[ONNX + metadata] --> Policy
```

**控制链路。** 网页、App 和已配置的物理手柄发出意图，服务检查当前任务与控制会话，再由总线拥有者执行。停止保持与卸力是不同操作；方向控制携带会话和递增序号，过期方向命令归零。动作、使能与模型推理由明确的用户操作启动，打开页面或恢复连接不会自动启动运动。

**模型链路。** 当前模型常用 61 维观测、14 维动作，嘴部为独立舵机控制。原生技能运行路径在控制循环中完成反馈、观测、推理与目标写入；兼容路径使用独立推理线程和最新结果槽。两条路径按各自合同执行，不将所有模型强行套用同一种滤波、增益或切换方式。机械范围、编码转换及故障处理集中在机器人端，客户端不重复实现策略。

**观测链路。** IMU 独立采集，关节反馈与模型控制共用串口拥有者，服务对外发布主题化遥测。WebSocket 按展示需要订阅最新数据，HTTP 提供元信息、快照、标定和控制接口。硬件采集频率、模型执行频率与浏览器展示频率分别管理；慢客户端不会要求服务积压全部传感器历史帧。

**运行与工具。** 机器人主服务、Wi-Fi 和电源辅助程序均为 Rust；推理使用原生 ONNX Runtime 动态库。Python 仅用于打包、部署、只读分析及部分测试工具，不作为机器人控制服务运行。音频调用系统 ALSA 播放器；可选摄像头由 Rust Observer 管理 V4L2/FFmpeg 子进程，与主服务共用 systemd 单元及 HTTP 端口，不运行 Python 摄像头服务。摄像头开关默认关闭，选择保存在主板；当前部署状态见实测记录。

## 主要功能

- **观测工作台：** 3D 身体姿态与 15 关节反馈、Roll/Pitch/Yaw、IMU 曲线、舵机电压/温度/电流/状态、CPU/内存/温度与部署版本。
- **标定：** 关节显示零位与方向、IMU 安装方向和参考姿态、Roll/Pitch 归零、显式硬件中位校准。显示标定与 EEPROM 写入分别处理。
- **实机控制：** 坐下预备、站立接行走、双摇杆网页手柄、速度设置、倒地起身、拾取、翻滚、左右脚踢球、零位，以及主板扬声器配合张闭嘴的“嘎一下”。
- **主板直连手柄（开发版）：** Linux evdev 输入复用控制后端；App BLE 与手柄连接可共存，显式动作获取控制权。物理手柄以双摇杆回中后的 LB+A 站立、LB+Y 倒地起身，Back 全局卸力。默认关闭，蓝牙配对、设备映射和双连接稳定性待实测，详见 [配置与验收要求](docs/GAMEPAD.md)。
- **诊断：** 控制状态与技能进度、反馈暂停、故障帧和会话记录、串口收发证据、日志筛选及 JSONL 导出。
- **连接与管理：** Web 自动重连及断线原因、BLE 绑定与认证、Wi-Fi 管理、Web 地址获取、确认后的主板关机/重启。

功能已接入服务不等于对应动作已在每种装配和姿态下通过验收；目前倒地起身和部分运动效果仍有用户反馈问题。

## 本地开发

需要 Linux / WSL、Rust 工具链，以及 Node.js 22.12+。生产 BLE 使用 Linux BlueZ。ONNX 推理需安装匹配的原生 ONNX Runtime，并设置 `ORT_DYLIB_PATH`。

启动隔离模拟服务：

```bash
cd backend-rust
MICRODUCK_SOURCE=simulation \
MICRODUCK_BLE_ENABLED=0 \
MICRODUCK_BIND=127.0.0.1:8877 \
cargo run --locked --bin microduck-observer
```

另一个终端启动网页：

```bash
cd frontend
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173`，连接 API `http://127.0.0.1:8877`。模拟数据有明确来源标识，不连接实物总线。生产构建的 `frontend/dist/` 由主服务直接提供，默认部署 Web 端口为 `8877`。

常用检查：

```bash
cd frontend
npm test
npm run build
```

```bash
cd backend-rust
cargo test --locked --bins
cargo build --release --locked --bins
```

外部模型 fixture、原生推理库和实机测试有独立环境要求；详细配置见 [Rust 后端](backend-rust/README.md)、[协议](protocol/README.md) 和 [当前工具](tools/README.md)。

| `backend-rust/src/` | HTTP / WS / BLE、遥测、串口控制、模型执行、共享标定与故障诊断 |
| `backend-rust/src/bin/` | Wi-Fi 和电源权限辅助程序 |
| `frontend/src/` | Web 页面、连接状态、3D 模型、图表与实机控制组件 |
| `models/` | ONNX 权重及观测顺序、来源和执行合同 metadata |
| `deploy/`、`tools/`、`scripts/` | 发布、回滚、只读测量及分析工具 |
| `protocol/` | 消息格式与接口约定 |
| `docs/实测记录/` | 按硬件与主题维护的实物记录、故障分析及原始证据 |

## 许可与资源来源

平台代码采用 [Apache-2.0](LICENSE)。机器人外形与部分策略资源来自公开项目，平台重构与资源来源分别记录：

- 3D 网格与模型描述的来源和转换说明见 [模型 NOTICE](frontend/public/model/NOTICE.md)，保留随附许可证。
- 当前部分策略权重来自 [kissqy/Microduck-kissqy](https://github.com/kissqy/Microduck-kissqy)，具体提交、权重哈希、观测合同和执行配置以 `models/*.metadata.json` 为准；自行训练的权重也在对应 metadata 中区分。

接入资源不代表本项目训练或原创全部模型；具体模型文件名兼容历史接口，不用于判断当前权重版本。上游资源的许可和署名随资源保留。
